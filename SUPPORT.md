### 🔍 OSS Health Audit

**What it covers**

Repository structure, CI pipelines, release process, documentation gaps, issue/PR flow, contributor experience, and maintenance risk signals.

**What you get**

A prioritized findings report with concrete fixes — not a generic checklist. Each finding includes: the risk it represents, the fix, and estimated effort. Delivered as a PR or document you can act on immediately.

**Who it's for**

- Teams taking over an inherited or unmaintained repository
- Maintainers preparing a major release or community hand-off
- Sponsors or employers asking "is this project healthy enough to depend on?"

______________________________________________________________________

### 🔄 API Lifecycle & Migration Sprint

**What it covers**

Versioning strategy, deprecation policy, migration warnings, compatibility layers, tests, and release notes for Python libraries undergoing a breaking change or long-term API evolution.

**What you get**

Working deprecation machinery (patterns from [pyDeprecate](https://github.com/Borda/pyDeprecate)), a migration guide for users, and a test matrix covering both the old and new API surface. Leaves your library with a documented deprecation process you can repeat on future changes.

**Who it's for**

- Library authors shipping a breaking v2 or v3
- Teams dealing with silent regressions from gradual API drift
- Maintainers who need to deprecate cleanly without breaking downstream users overnight

______________________________________________________________________

### 👁️ Computer Vision Pipeline Reliability Sprint

**What it covers**

Detection, segmentation, tracking, adapter, fixture, evaluation, and reproducibility gaps in CV systems built on detection/tracking stacks.

**What you get**

Identified gaps, added fixtures for critical adapter paths, reproducibility documentation, and a reliability report with actionable items ranked by risk to production.

**Who it's for**

- Teams shipping CV systems to production who need confidence their pipeline handles edge cases
- ML engineers inheriting a CV codebase with unclear test coverage

### 🤖 AI-Assisted Maintainer Workflow Setup

**What it covers**

`.github` defaults, AI-Rig-style review workflows, release checks, PR Evidence Cards, and human-in-the-loop review calibrated to your team's risk tolerance and repo size.

**What you get**

A configured `.github` overlay, working agent workflows for code review and release audit, a release checklist, and documented review processes your team can maintain. Based on patterns from [.github](https://github.com/Borda/.github) and [AI-Rig](https://github.com/Borda/AI-Rig).

**Who it's for**

- Maintainers who want AI in their loop without losing control or shipping hallucinated reviews
- Teams scaling review capacity without scaling headcount
- OSS projects preparing for community growth who need consistent triage and release hygiene
